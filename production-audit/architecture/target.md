# Target Architecture

The target is the smallest change set that removes the defects proven by source review
and by executed tests, while preserving the existing service boundaries, the existing
event contracts and the existing fleet conventions in `docs/PATTERNS.md`.

The guiding rule is that a pattern is introduced only when it fixes a proven defect or
removes a proven source of ambiguity. Nothing is added for symmetry.

## 1. Payment provider boundary

The provider port gains an explicit outcome vocabulary instead of a boolean.

```
ProviderResult
├── CONFIRMED             the provider verified that the money moved
├── REQUIRES_CONFIRMATION the intent exists and the client must confirm
├── REJECTED              the provider definitively refused
└── INDETERMINATE         the provider call did not reach a verdict
```

`accepted()` becomes true only for `CONFIRMED`. A payment reaches `CAPTURED` only on a
`CONFIRMED` result. An unknown provider name is rejected with
`ErrorCode.PAYMENT_PROVIDER_REJECTED` instead of silently falling back to the default
provider. The mock provider is selectable only when it is the configured provider.

The provider intent identifier and the client secret are persisted with the payment, so a
refund addresses the original intent directly instead of searching an eventually
consistent index.

## 2. Gateway rate limiting

The three bucket layers collapse into one Lua script and one policy object. The script
takes the route, the scope and the identity key, applies the per-route budget, the
fleet-wide budget and the edge budget in a single round trip, and returns the decision
together with the remaining counts.

That change removes the contradictory failure policy, where the two framework layers
fail open and the custom layer fails closed, and it removes the inconsistent 429
contract, where one layer returns an empty body and another returns an envelope with a
sentinel value.

The client address is resolved from the peer address and the configured trusted proxy
hops only. The trusted proxy list is an explicit allowlist, and the value that enters
the bucket key is validated as a literal address before it is used, so a crafted
forwarding header can neither bypass the budget nor trigger a name resolution on the
event loop.

The edge budget reads the clock from Redis, like the framework layers, so replicas share
one time base.

## 3. Kafka publication and consumption

Producers keep `acks=all` with idempotence. Producer transactions are deliberately not
introduced: a PostgreSQL write and a Kafka transaction cannot be committed together
without a distributed transaction coordinator, so a producer transaction would add
ceremony without adding atomicity.

The outbox claim query stops using a minimum-identifier subquery, because a skip-locked
claim over that shape lets a second replica select nothing and publish nothing. The
claim becomes an ordered scan over a claimable set.

Every consumer that performs a side effect keeps a durable inbox record under a unique
constraint. Consumers that only apply snapshots keep the snapshot discipline and gain a
regression test that proves a duplicate or out-of-order delta cannot double-apply.

Every listener receives a dead-letter recoverer. A listener without a recoverer logs and
skips the record, which loses the event silently. The dead-letter replay service keeps
its committed offsets, so a replay pass does not re-publish from the beginning of the
topic, and the replay endpoint is authorised and restricted to contracted topics.

## 4. Identity and authorization

The subject carried by the token is the only identity key. The service resolves the
platform user through the Keycloak identifier column and never through the generated
primary key, so the self-service profile and address surfaces work.

The verified-purchase endpoint binds the requested user identifier to the authenticated
principal. A service-role caller must present an authorised-party identifier that is
bound to the requested user, and the guard fails closed when the security context is
empty.

The authorisation primitive fails closed. A guard that returns when the context is
absent is an allow-by-default primitive, and it is used on endpoints that expose
another user's order data.

## 5. Correlation and client address

The correlation identifier is generated by the platform when the client does not supply
one, and a supplied value is accepted only when it matches a strict character and length
policy. The client address is taken from the peer address, with the forwarding header
consulted only through a configured trusted proxy list.

The response logging wrapper is given a size cap, so a large response is not buffered
in heap for every request.

## 6. Storage and networking

The object storage bootstrap moves the bucket existence check out of the bean creation
method into a startup listener with a timeout, and the bucket creation becomes
idempotent under concurrent replicas.

The Keycloak admin client replaces the monitor held across the token refresh with an
asynchronous cache, and the service-account configuration fails fast when it is only
half configured instead of silently downgrading to the master-realm password grant.

## 7. What the target deliberately does not change

- The service boundaries and the database-per-service model.
- The event contracts and the topic names.
- The REST routes and the request shapes.
- The fleet conventions in `docs/PATTERNS.md`.
- The outbox atomicity guarantee, which is already correct in all eight services.
- The cross-replica safety of the gateway buckets, which is already correct because
  every mutation is a single Lua script.
